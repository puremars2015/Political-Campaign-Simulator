# 《選戰辦公室：距離投票還有90天》開發計畫

文件狀態：第二版開發基準；真實候選人、全陣營真實政見與縣市優先選角為必要需求。

建立日期：2026-10-28（Asia/Taipei）。

更新日期：2026-10-29（Asia/Taipei）。

產品類型：單人、文字敘事、回合決策、政治模擬網頁遊戲。

## 1. 產品目標

玩家先選擇縣市，再從該縣市2026年縣市長選舉的真實候選人中選擇一位，成為其競選辦公室主任，在時間、預算、候選人立場、團隊壓力、民調與選票之間做選擇。玩家負責推進選戰，但無法完全控制候選人、組織與事件。

核心體驗是：**「我一開始明明不打算做這個承諾，但我記得，是哪幾次看似合理的選擇，讓我們走到了這裡。」**

遊戲應讓玩家理解，真實政見如何在合理但互相衝突的要求中被選擇、排序、包裝與推到選戰中心。勝選是重要目標，但結局也應呈現團隊、信用與承諾的代價。玩家不能替真人創造未曾提出的政見；「製造政見的壓力」透過既有政見的取捨、曝光與既有歷史版本之間的張力呈現。

### 1.1 設計原則

- 玩家扮演有影響力但受限制的競辦主任，不是全知的候選人操控者。
- 困境來自可理解的因果與資源限制，不能只是所有選項都會受罰。
- 政策選擇有不同價值與成本，不標記標準道德答案。
- 保留談判、延後宣傳、調整議題優先序、維持原則與承受代價的空間，不允許捏造政見內容。
- 民調是有誤差、延遲與解讀爭議的資訊，不是每次選擇的即時分數。
- 重要後果能透過事件紀錄追溯，但不必立即揭露隱藏選情。
- 真人公開紀錄、模型推論與遊戲虛構必須可以區分。
- 我方、主要對手、第三方及其他參選人的政見，均須出自該候選人的真實公開主張並附來源；不因陣營或遊戲角色不同而降低查證標準。
- 不以隨機或合成候選人替代正式選角；隨機性只用於模擬事件、資源擾動與選情。

### 1.2 參考作品與查證狀態

參考網址：https://1in8b.life/zh/ 。採用使用者提出的「隨機人生、事件選擇、累積後果」作為設計方向。

規劃時該網站回傳 HTTP 403，尚未驗證其實際介面、數值機制或完整流程。後續如能正常存取，再補充玩法分析；現階段不宣稱已重現參考作品，也不複製其素材、文案或視覺設計。

政見資料呈現另參考使用者指定的 https://blindvote.app/ 。本次讀取同樣回傳 HTTP 403，尚未確認其來源標示、資料授權或實作細節。現階段將「政見可以比較、摘要可以回查原文、每筆主張附出處」列為本遊戲的自主規格，不宣稱該網站已採用特定機制，也不預設可以直接抓取或轉用其資料。

### 1.3 本次需求調整

1. 可輔佐的人物必須是真實存在、參與該屆該選區選舉的候選人。
2. 遊戲內所有陣營政見必須有真實依據與可查閱來源，取消虛構政策與替真人自由創造新承諾的玩法。
3. 開局固定為「選縣市 → 選該縣市候選人 → 查閱資料並確認 → 進入遊戲」。
4. 真實資料由後續擴充項目前移為原型與首版的必要依賴；正式首版範圍為全台22縣市首長選舉。

## 2. 背景與版本範圍

正式內容以2026年台灣地方選舉為背景，可選職位限定六都直轄市長及其餘縣市的縣市長，不包含議員、鄉鎮市長、村里長或其他職位。

縣市目錄包含以下22個選區：

- 六都：臺北市、新北市、桃園市、臺中市、臺南市、高雄市。
- 其餘市：基隆市、新竹市、嘉義市。
- 縣：宜蘭縣、新竹縣、苗栗縣、彰化縣、南投縣、雲林縣、嘉義縣、屏東縣、臺東縣、花蓮縣、澎湖縣、金門縣、連江縣。

內部垂直切片可先完成一個真實縣市，但必須採用已查證的真實候選人與多方政見，不再使用虛構縣市或合成人物作為可玩內容。未完成資料的選區顯示進度，不提供假名或補造政見；不能將部分選區完成宣稱為正式首版完成。

- 無限制自由輸入政見或自動生成真人事件。
- 真實選情預測、實際競選成效評估工具。
- 選後完整施政模擬；首版以結局呈現承諾負擔。

## 3. 玩家旅程與核心循環

### 3.1 開局

1. 選擇縣市：以六都與其他縣市清單或可操作地圖呈現22縣市，標示資料截至日期與可玩狀態。
2. 選擇候選人：只列該縣市、該屆、該職位的候選人，顯示姓名、政黨或無黨籍、參選狀態、資料完整度及來源入口。
3. 閱讀候選人介紹、當次真實政見、歷史立場與同選區對手資料，確認輔佐對象。
4. 說明政見與候選人為真實資料，內部對話、資源、民調變化及選舉結果為模擬；確認後才建立新局。
5. 載入該選區的多方候選人與版本固定的政見資料，接到第一份簡報並進入教學事件。

正式遊戲不隨機分配候選人，也不要求先玩一局才開放選角。選情與辦公室起始條件可有明確標示的模擬差異。返回更換縣市時清除尚未確認的候選人選擇；既有存檔不因瀏覽選角頁而被覆寫。

候選人名單與政見不足時，顯示缺少資料的原因，不得以「未提供」推論成反對某議題。登記前區分宣布參選、獲提名與正式登記等狀態；正式可玩名單以選務機關公告為準。提名或宣布參選資料可供查閱，但不得冒稱正式候選人。名單尚未定案時明確標示，不能宣稱當屆名單完整。

### 3.2 每回合流程

**閱讀簡報 → 安排行動 → 處理事件 → 協調公開立場 → 結算與保存。**

- 簡報：新聞、民調、群組訊息、資源與待處理承諾。
- 行動：政策研究、議題回應、行程、團隊照顧、調查或危機處理。
- 事件：提供情境、期限、選項與可理解的代價提示。
- 協調：候選人可能接受、要求修改或拒絕議題排序及宣傳安排；對話反應屬模擬，不能增加無來源政見。
- 結算：呈現已知結果，排入延遲後果，推進日期並自動存檔。

初始每回合配置三個行動點，行動成本與數值在平衡測試後調整。免費閱讀資料不消耗行動點；高成本行動必須在確認前說明。延後處理也必須有明確規則與紀錄。

### 3.3 12回合節奏

| 回合 | 敘事定位 | 系統重點 |
| --- | --- | --- |
| 1–3 | 接手、盤點與建立關係 | 教學、初始承諾、候選人信任 |
| 4–6 | 政見取捨與議題交鋒 | 資源競爭、真實主張的曝光、早期後果 |
| 7–9 | 壓力累積與立場檢驗 | 歷史矛盾、延遲後果、團隊疲勞 |
| 10–12 | 投票前逐日倒數 | 有限修正、承諾鎖定、最後決策 |

每個回合保存明確的日期區間；前三階段合計覆蓋至投票前三天，最後三回合逐日推進。投票與開票在第12回合結束後觸發。

## 4. 模擬系統

### 4.1 玩家可見的主要狀態

| 狀態 | 用途 | 呈現原則 |
| --- | --- | --- |
| 經費 | 支付調查、活動與其他行動 | 顯示餘額與支出紀錄 |
| 時間／行動點 | 限制同回合能處理的事 | 明確顯示剩餘額度 |
| 團隊士氣 | 影響執行能力、疲勞與離職事件 | 數值搭配成員訊息 |
| 候選人信任 | 影響建議是否被接受、談判空間 | 說明關係變化的已知原因 |
| 公共信任 | 累積承諾可信度與言行影響 | 呈現有誤差的內部評估，不當作客觀讀心值 |
| 政策一致性 | 紀錄宣傳重點與有來源的歷史承諾之間的關係 | 能展開查看原文、時點與模擬中的取捨 |

關係、承諾、事件旗標與疲勞細節可作為次級狀態，避免首頁變成過度複雜的儀表板。數值上下限、成本與效果集中配置，不分散寫在介面中。

### 4.2 候選人自主性

候選人具有有來源的公開履歷、議題立場與歷史紀錄；性格、內部優先事項與可協商範圍屬明確標示的模擬參數。玩家提出行程、議題排序或回應方案後，系統依已查證立場、當前信任、事件壓力與歷史選擇決定模擬回應。任何陣營的政策內容都不得由性格參數或事件隨機生成。

- 接受：按提案執行。
- 協商：調整宣傳安排或選用另一項已查證政見，玩家仍能選擇。
- 拒絕：說明理由與目前可用的替代方案。
- 自行決定：僅在事件預先定義且條件成立時發生，必須留下因果紀錄。

信任提供談判空間，但不應讓所有原則都能靠刷好感度取消。重要限制應提前透過簡報、對話或公開紀錄提示。

### 4.3 政見承諾系統

系統拆成「唯讀的真實政見庫」與「本局的宣傳決策紀錄」，不得讓玩家操作覆寫候選人事實。

每項真實政見至少包含候選人ID、屆次、選區、議題、忠實摘要、原文引句、出處及版本。政策工具、規模、財源、期限與措辭強度只記錄來源確實提供的資訊；未交代的欄位明確標示「來源未說明」，不可為了讓遊戲可計算而補成事實。

玩家可操作：

- 在本人已提出的政見中選擇本週主打項目與曝光順序。
- 分配說明、查核、行程與議題回應資源。
- 選擇來源支持的解說角度，不改變主張、適用對象、金額、期限或承諾強度。
- 面對對手政見時引用我方既有主張、要求查核，或延後回應並承擔遊戲代價。

本局狀態流程：待宣傳 → 內部協調 → 主打／延後／降低曝光 → 結局回顧。這些是模擬中的競選安排，不代表真人實際公布、撤回或改變政策。

只有公開來源證實曾發生的政策修訂、撤回或反轉，才可成為真實政見版本。舊立場不能直接當成2026當次政見；歷史與當次資料分開顯示。每局固定資料版本，若採歷史時序模式，不得提前引用當時尚未發布的資料；若採截至日期快照模式，必須標示90天為敘事壓縮，不是逐日史實重演。

每次宣傳調整保留回合、事件、政見版本與玩家決策。財源與可行性的遊戲評估需標示為模型推論，並提供依據；不得把「來源未說明」等同於沒有財源或無法履行。

### 4.4 民調與隱藏選情

分開保存三種資料：

1. 模擬中的實際選情：候選人支持、未表態與投票傾向等隱藏狀態。
2. 民調觀測：調查時間、樣本數、調查方式、支持率、未表態與不確定性。
3. 幕僚解讀：從可見資訊形成的判讀，可能不完整。

我方與所有同選區對手都以該屆真實候選人為對象。預設民調及其變化為模擬資料並顯著標示；若引用真實民調作為起始參考，另附調查機構、調查日期、方法及來源，不能混同後續模擬民調。

行動效果不直接等於得票效果；聲量、信任與支持需分開處理。政策影響可有延遲，調查不一定反映當下最新變化。

首版先採固定抽樣模型，定義清楚支持率分母、未表態處理與誤差呈現方式。調查方法的誤差說明必須與實際模型相符；不把抽樣誤差當作涵蓋所有不確定性的保證。

買更多調查可減少部分資訊盲點，但不能直接讀取隱藏狀態。一般遊戲畫面不揭露引擎真值，開發工具可查看以協助除錯。

### 4.5 事件與延遲後果

事件由前置條件、觸發窗口、選項、即時效果、延遲效果與後續事件組成。主線事件確保節奏，條件事件回應玩家歷史，隨機事件提供變化。

- 不同候選人可共用事件骨架，但對話、可用選項與反應應不同。
- 事件中任何陣營的政策主張都必須引用對應候選人的已審閱政見版本，不得把其他縣市、他人或不同屆次的政策移植過來。
- 未取得對手在某議題的主張時，呈現「尚無可核對資料」，不能補造政策或推論其支持／反對。
- 一次性事件不可重複觸發；互斥事件需有明確群組。
- 關鍵後果必須保存來源決策，供回顧與開發檢查。
- 任何資源狀態下都須存在有效選項，避免流程卡死。
- 經費不足或士氣低落應開啟有代價的替代路徑，不直接令遊戲無法繼續。

事件題材包含居民陳情、政策爭議、冷清活動、幕僚離職、採訪、辯論、失言與內部協調，不以醜聞作為唯一戲劇來源。

### 4.6 代表事件：補助承諾

這是一個待綁定真實資料的事件模板，不是任何真人事件的事實陳述。資料條件為：同選區對手確實提出補助政見、我方確有相關議題政見，且每項主張都有已審閱來源。若使用我方歷史批評，還須有對應引文與日期；條件不足則不載入此版本。

模擬情境：記者詢問對手已提出的補助政策，距離記者會還有20分鐘。內部團隊對於應否將我方相關政見推為主打產生分歧。

| 選擇 | 當下代價 | 可能延遲後果 |
| --- | --- | --- |
| 引用我方既有政見，說明差異 | 準備時間與曝光機會 | 維持主張，可能遭遇新的議題追問 |
| 將我方另一項已提出的相關政見改為主打 | 協調與行程調整成本 | 其他政見曝光減少，團隊優先序改變 |
| 先查核雙方來源，延後政策回應 | 時間與新聞機會 | 說明較完整，但須處理延後回應的壓力 |
| 沿用已查證的公開說法，不追加承諾 | 降低即時衝突但可能缺乏新意 | 保留資源，承受模擬中的曝光壓力 |

具體結果由候選人的模擬參數與先前事件共同決定。選項提示描述已知成本，不提供固定的「支持度＋3」答案。任何選項都不能新增或竄改雙方真實政見；敘事與結果標示為模擬。

## 5. 結局與開票

投票模型根據隱藏支持、未表態分配、投票傾向與有界隨機因素產生結果。模型參數必須配置化，經模擬測試檢查，不宣稱對真實選舉具預測能力。

開票以所選縣市及其有來源的行政區資料逐步揭曉，各候選人票數皆為模擬並清楚標示。票數加總須一致；平票與其他邊界情況須有明確的遊戲規則。開票隨機性不能任意抹去玩家整局累積的影響。

結局包含四份回顧：

- 選票：得票、差距、模型中主要影響因素。除非實際運算反事實比較，不宣稱某次選擇精確造成多少票。
- 承諾：真實政見出處、玩家主打與延後項目的時間軸；已查證的真人立場變化與玩家宣傳選擇分開呈現。
- 團隊：成員去留、士氣、候選人關係。
- 代價：若當選，尚未解決的財源、可行性與期限；若落選，留下的組織與政策成果。

勝選但失去政策主導權、落選但維持團隊等結果，都應有完整敘事。結局不提供單一的道德總分。

## 7. 技術方案與資料模型

### 7.3 引擎契約與存檔

- 相同初始種子、內容版本與選擇序列，必須得到相同結果。
- 隨機抽樣一律透過可保存狀態的亂數產生器，不直接呼叫散落的隨機函式。
- UI 提交行動，引擎驗證前置條件與成本，再一次性產生新狀態與紀錄。
- 拒絕不合法行動時不扣資源、不推進時間。
- 決策提交與回合結算後自動保存；重複點擊不可重複扣款或套用效果。
- 保存完整狀態與決策紀錄，不依賴重新整理後重新抽取事件。
- 內容或schema版本不相容時明確說明；不得靜默重置舊存檔。
- 存檔固定縣市、參選名單與政見資料版本；資料更新後仍能查閱當局依據，不將退選、換人或政策更新靜默套入舊局。
- 儲存失敗時提示使用者並保留當前畫面狀態，不能假裝已保存。

## 8. 全陣營真實政見與資料來源規範

真實資料是所有可玩版本的前置條件，不是後續選配。每個可玩選區須涵蓋同屆所有正式候選人，依相同標準查證；不因我方、對手、政黨或知名度決定引用門檻。文件本次僅修訂開發規格，尚未完成2026候選人清單或政見蒐集。

### 8.1 資料蒐集

- 參選與選制資訊優先使用選務機關的正式資料。
- 政見優先使用選舉公報、候選人官方政見文件、官方網站、正式記者會或有完整上下文的公開發言；可靠媒體可交叉查證，不以搜尋摘要或二手轉述作為唯一依據。
- 每筆立場附來源、日期、適用職位與情境，保留修正歷程。
- 標示資料截至日期；未宣布、待確認與已確認分開處理。
- 未取得證據時保留未知，不自行補成候選人的既定主張。
- 政黨主張不自動等於每名候選人主張；他人政策不能直接歸給同黨候選人。歷史施政成果也不能自動視為當次競選承諾。
- 行政區、名單與政見資料記錄使用授權；引用保留必要篇幅與上下文，不預設參考網站的內容可整批重用。

### 8.2 事實、推論與虛構

- 公開紀錄可引用並追溯來源。
- 性格參數與協商邊界是設計推論，需標示並人工審閱。
- 競辦對話與內部事件是虛構，不當作私人動機的事實陳述。
- 陣營間關係也是模擬，不把真實對手描述成已證實的私下盟友；對話中的政策說法仍須綁定來源。
- 不將虛構醜聞、犯罪或利益交換套在真人身上。
- 遊戲內提供查閱來源與辨識內容性質的入口。
- 如未來使用生成式文字，只能在審核過的事實與情境範圍內改寫，不自由生成真人事實。

### 8.3 政見比較與來源介面

每張政見卡都能展開查看候選人、選區／屆次、忠實摘要、原文引句、來源標題、發布者、日期及連結。PDF提供頁碼、影片提供時間碼，網頁提供段落或可定位的引文。來源已失效時明示狀態，提供合法保留的存檔或替代出處；沒有可核對證據的資料不得新上線。

比較頁以同一議題並列多方主張，保留原始範圍、條件與措辭強度，不為了對齊欄位而改寫成相同問題的支持／反對。缺資料顯示「尚未取得可核對的公開主張」，不填成中立、反對或零分。

可提供「先看政見、再揭曉候選人」的可選比較模式，作為本遊戲的設計提案，不宣稱已驗證參考站採用此流程。此模式只影響比較頁顯示，不取代開局的縣市與候選人選擇；揭曉後仍可立即查看出處。

### 8.4 資料製作與發布門檻

流程：確認名單與資格來源 → 蒐集多方政見 → 拆成可引用主張 → 摘要與原文比對 → 人工審閱 → schema及引用驗證 → 綁定事件 → 發布有日期的資料版本。

- 每個使用中的政策主張至少連結一筆已審閱來源；不同主張不能僅以不相關的候選人首頁作為共用證據。
- 查核候選人、選區、職位、屆次與時間，確認引文支持實際摘要；「有連結」不等於內容有依據。
- 建立各選區／候選人／議題覆蓋表，記錄已查證、未公布、待查證與不適用，避免僅完整蒐集主流候選人。
- 資料不夠支撐某事件時停用該事件，使用不需要該主張的替代事件，不生成補位政見。
- 某候選人資料不足以支撐完整一局時，清楚標示尚不可玩；該選區不能通過正式發布驗收。
- 名單變更、退選、來源更正及政策更新均有版本與異動紀錄；新局採新版本，舊局維持原資料並提示更新。
- 正式發布前重新核對選務機關名單與資料截至日期。若名單尚未定案，只能標示為預覽資料，不能宣稱覆蓋正式全體候選人。

## 9. 開發階段與交付條件

以下按依賴順序推進，以交付條件估算工作，不預先承諾缺乏人力依據的日程。

### M0：真實名單、來源庫與內容骨架

交付：22縣市目錄與覆蓋表、一個真實縣市的候選人清單與資格來源、該選區多方政見及原文定位、12回合日期配置、事件schema及三個綁定真實主張的代表事件。

驗收：沒有虛構候選人；各項用到的政見均有正確歸屬與來源；每個事件具備前置條件、代價與可追溯後果；資料驗證能指出缺漏、跨屆誤用與無效引用。尚未確認資格或資料不齊的對象不得進入可玩清單。

### M1：可完整操作的垂直切片

交付：專案基礎、規則引擎、縣市→候選人→確認的開局流程、先行縣市的前三回合、一次政見宣傳取捨、一次候選人協商、一次延遲後果、來源展開與自動存檔。

驗收：只可選取所選縣市的當屆候選人；切換縣市不殘留原選角；玩家能完成開局至第三回合；對手主張與我方主張都能查閱原文；重新整理能繼續；相同種子與選擇能重現結果；至少一項早期選擇會改變後續事件，且未改寫真人政見。

### M2：完整 MVP

交付：全台22縣市的正式候選人目錄與可玩資料、約30個可依來源條件重組的事件模板、完整12回合、民調、投票模型、開票與四份結局回顧。每個候選人都須有足以支撐整局的已審閱內容，不以模板總數替代實際覆蓋。

驗收：22縣市均完成名單核對，各正式候選人均可被選取並完成一局；正常與低資源路徑均不會卡死；所有陣營出現的政見均有已審閱來源；宣傳紀錄不修改真實政見；開票票數一致；支持率與資源不出現不合法數值。任一選區未達門檻時，只能交付明示範圍的測試版，不得標示完整MVP已完成。

### M3：試玩、平衡與可及性

交付：手機版改善、鍵盤操作、錯誤處理、平衡報告與修訂內容。

至少邀請五名未參與開發者試玩，紀錄實際遊玩時間、誤解與卡關位置。觀察玩家能否解釋一次宣傳優先序改變、感受到候選人自主性，並區分真實政見、模擬對話、模擬民調與開票。確認玩家能自行找到我方及對手主張的來源。若玩家只是在尋找固定最高分答案，優先調整回饋與事件因果。

驗收：核心流程無阻斷問題；主要選項有可理解的取捨；不同候選人出現不同選擇空間；沒有一項重複行動在所有情境下都支配其他行動。

### M4：資料更新與正式發布複核

交付：全台名單與來源庫的更新流程、資料更正紀錄、來源失效處理、人工審閱紀錄、舊局版本保留與事實／推論／虛構標示複核。

驗收：發布時再次確認全部候選人狀態、職權與政見版本；公開紀錄可追溯；虛構事件不被呈現成真人事實；模擬操作不被記成真人立場；資料更新不破壞既有存檔。M4是既有真實資料的持續維護與發布複核，不是延後實現M0至M2的真實資料要求。

## 11. 主要風險與處理

| 風險 | 處理方式 |
| --- | --- |
| 選項看似不同、後果卻一樣 | 在垂直切片先驗證會改變後續事件的決策 |
| 所有決策都懲罰玩家 | 同時設計可獲益的協商與有代價的原則路徑 |
| 候選人自主性讓玩家失去參與感 | 提前提示限制，保留替代方案，建立信任可換取的談判空間 |
| 民調變成即時得分表 | 分離聲量、信任、支持與調查觀測，延遲呈現部分結果 |
| 隨機性蓋過玩家決策 | 限制擾動範圍，檢查固定種子下決策差異與結局分布 |
| 內容組合爆量 | 共用事件骨架，以條件與候選人差異控制分支數量 |
| 真人資料過期或失真 | 保存來源與截至日期，設立更新與審閱門檻 |
| 部分陣營缺資料或名單尚未確定 | 保留未知並標示進度，不補造主張、不冒稱已完整發布 |
| 玩家選擇被誤認為真人新政策 | 分離唯讀政見與宣傳紀錄，限制選項只能使用已查證內容 |
| 模擬被誤認為預測 | 開局、民調與結局標示遊戲模型性質 |
| 全台內容量影響開發進度 | M1先做一個真實縣市，M2依覆蓋表擴至22縣市；不擴增其他職位、後端或生成式服務，也不縮減正式首版需求 |
